# BioMni Agent Improvements: Reducing Hallucinations

This document outlines recent updates to the BioMni agent aimed at significantly reducing hallucinations and improving the reliability of its outputs. The primary focus has been on two areas: ensuring accurate interaction with the data lake and providing a mechanism for auditing the agent's performance.

-----

## The Problem: Agent Hallucination

The agent exhibited two main types of hallucinations:

1.  **Data Interaction Failures:** When tasked with analyzing a dataset from the data lake, the agent would often guess (hallucinate) column names. This frequently caused code execution to fail. Even when the agent correctly listed the columns, it sometimes struggled to identify the relevant ones for the task, leading it to fall back on its internal knowledge to generate a plausible but unsubstantiated result.
2.  **Undetected Internal Knowledge Usage:** The agent could produce a final answer that appeared correct on the surface, but was actually derived from its internal knowledge rather than the provided data and tools. This made it difficult for users to trust the results and identify when a hallucination had occurred.

-----

## Solutions Implemented

To address these issues, two primary solutions have been developed and integrated into the agent's workflow.

### 1\. Reliable Data Lake Interaction

To prevent the agent from guessing dataset schemas, a new tool and a corresponding enforcement mechanism have been introduced.

#### Data Catalog Tool

A new tool has been created to provide the agent with structured metadata about files in the data lake before it attempts to access them.

  * **Location:** `biomni/tool/data_catalog_tool.py`
  * **Description:**
    ```python
    def get_metadata(filename: str) -> dict:
        """
        Retrieves the pre-generated metadata for a specific file from the data lake catalog.

        This tool allows an agent to quickly understand the schema and contents of a dataset
        without having to parse the file itself.

        Args:
            filename (str): The name of the file (e.g., "proteinatlas.tsv") to look up.

        Returns:
            dict: The metadata dictionary for the requested file.
                  Returns an error message if the file is not found in the catalog.
        """
    ```

#### Metadata Generation

The metadata required by the `data_catalog_tool` is pre-generated by a new scanner script.

  * **Script:** `biomni/scanner.py`
  * **Usage:** This script takes the path to the data lake folder as input.
  * **Output:** It generates a `data_lake_metadata.json` file, which serves as the catalog for the `Youtube` tool.
  * **Location:** `data/biomni_data/data_lake_metadata.json`

**Example Metadata Entry:**

```json
{
  "msigdb_human_c5_ontology_geneset.parquet": {
    "description": "Human MSigDB C5 (GO: Biological Process) gene sets linking GO terms to their MSigDB IDs and member gene symbols.",
    "columns": {
      "go_term_name": "chromosome_id",
      "msigdb_collection": "collection",
      "msigdb_geneset_id": "systematicName",
      "go_term_id": "exactSource",
      "pubmed_id": "pmid",
      "gene_symbols": "geneSymbols"
    }
  }
}
```

#### System Prompt Enforcement

The system prompt has been modified to explicitly instruct the agent to use the new `data_catalog_tool` tool as its first step before interacting with any dataset.

**Key addition to the system prompt:**

```text
Import file: biomni.tool.data_catalog_tool
===========================================
Method: get_metadata
  Description: Retrieves the pre-generated metadata for a specific file from the data lake catalog. This tool should be used first to understand a file's schema before attempting to read it.
  Required Parameters:
    - filename (str): The name of the file (e.g., "proteinatlas.tsv") to look up.
---
[...]
IMPORTANT: Before interacting with any dataset, your FIRST step MUST ALWAYS be to understand its structure using the get_metadata function. Only when this step is done you can proceed to read the dataset.
```

This change forces the agent into a more reliable workflow: inspect first, then act.

### 2\. Agent Performance and Knowledge Auditor (APAK)

To address the issue of subtle, hard-to-detect hallucinations in the final output, a new critic agent, **APAK**, has been introduced.

**APAK: Agent Performance and Knowledge Auditor**

APAK is a separate agent that runs at the conclusion of the BioMni agent's workflow. It analyzes the entire conversation history to provide a structured critique of the primary agent's performance and to flag instances where internal knowledge was used.

  * **Input:** The full history of messages between the user and the BioMni agent.
  * **Output:** A JSON object detailing its audit. This structured output is designed for easy integration into a UI, allowing for features like highlighting specific lines where the agent potentially hallucinated information.

**APAK Output Structure:**

```json
{
  "overall_summary": "A brief, one-paragraph summary of the agent's performance.",
  "performance_assessment": {
    "plan_adherence": { "score": 1, "justification": "..." },
    "reasoning_quality": { "score": 1, "justification": "..." },
    "tool_usage": { "score": 1, "justification": "..." },
    "error_handling": { "score": 1, "justification": "..." },
    "solution_quality": { "score": 1, "justification": "..." }
  },
  "internal_knowledge_audit": [
    {
      "line_number": 0,
      "text": "The exact quote from the agent's reasoning or solution.",
      "justification": "Explanation of why this is internal knowledge (e.g., 'This curated list of genes was not provided by any tool output.')."
    }
  ]
}
```
